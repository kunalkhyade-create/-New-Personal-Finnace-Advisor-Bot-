## Authentication

FinanceBot does not require user authentication. The **Gemini API key** is optional and can be
supplied via three mechanisms, in priority order:

| Priority | Mechanism | Example |
|---|---|---|
| 1 | JSON body field `api_key` | `{ "api_key": "AIza..." }` |
| 2 | Request header `X-Gemini-API-Key` | `X-Gemini-API-Key: AIza...` |
| 3 | Server environment variable | `GEMINI_API_KEY=AIza...` in `.env` |

If no valid key is found, the **Smart Advisory Engine** is used automatically (no error).

## Endpoints

### GET /

Renders the main single-page UI.

**Response:** `200 OK` — HTML page

**Notes:**
- The route passes `categories`, `goals`, and `has_api_key` to the Jinja2 template.
- No JSON response.

### POST /analyse

Core endpoint. Validates the financial data, calls the Gemini AI (if a key is present) or the
Smart Advisory Engine, and returns a full budget plan with analysis and suggestions.

**URL:** `POST /analyse`

**Request Headers:**

| Header | Required | Description |
|---|---|---|
| `Content-Type` | Yes | Must be `application/json` |
| `X-Gemini-API-Key` | No | Optional API key override |

**Request Body:**

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `income` | number | Yes | `> 0`, `<= 10,000,000` | Monthly net income in INR |
| `expenses` | object | Yes | At least one valid key with value `>= 0` | Category-to-amount map |
| `goal` | string | No | One of 8 valid goal keys | Defaults to `"emergency_fund"` |
| `api_key` | string | No | — | Optional Gemini API key override |

**Valid `expenses` category keys:**
`rent`, `food`, `transport`, `dining`, `entertainment`, `utilities`, `savings`, `health`, `education`, `shopping`, `other`

**Valid `goal` values:**
`emergency_fund`, `vacation`, `gadget`, `investment`, `debt_repayment`, `home_purchase`, `retirement`, `education`

**Example Request:**

```json
{
  "income": 75000,
  "expenses": {
    "rent": 20000,
    "food": 8000,
    "transport": 3000,
    "dining": 4000,
    "entertainment": 2000,
    "utilities": 2500,
    "savings": 10000
  },
  "goal": "emergency_fund"
}
```

**Success Response — `200 OK` (Gemini mode):**

```json
{
  "success": true,
  "source": "gemini",
  "model": "gemini-2.0-flash",
  "budget": [
    {
      "category": "Rent / Housing",
      "recommended": 22500,
      "actual": 20000,
      "percentage": 30,
      "status": "ok",
      "tip": "Housing expenses are well balanced within the 30% threshold."
    },
    {
      "category": "Groceries and Food",
      "recommended": 11250,
      "actual": 8000,
      "percentage": 15,
      "status": "under",
      "tip": "Food budget is lean; ensure nutritional balance is not being compromised."
    }
  ],
  "analysis": [
    {
      "category": "Rent / Housing",
      "actual": 20000,
      "recommended": 22500,
      "percentage_used": 27,
      "status": "ok",
      "insight": "Rent is well-controlled at 27% of your monthly take-home income."
    }
  ],
  "suggestions": [
    "Automate a SIP of Rs.15,000 in Nifty 50 index funds on the 1st of every month.",
    "Cap weekend dining at Rs.3,200 to redirect Rs.800 monthly to your emergency fund.",
    "Switch 2 commute days to public transit to save Rs.600 every month.",
    "Target saving at least 20% of your net income (Rs.15,000) immediately when your salary is credited."
  ],
  "summary": "Your total expenses are Rs.49,500 (66% of income), generating a healthy disposable surplus of Rs.25,500. Following the recommended allocations will keep you disciplined on your journey to build a 6-month emergency fund."
}
```

**Success Response — `200 OK` (Smart Engine mode):**

```json
{
  "success": true,
  "source": "smart_engine",
  "has_api_key": false,
  "note": "Generated by Smart Advisory Engine. To use live Gemini 2.0 AI, set GEMINI_API_KEY in .env or via the API Key button.",
  "budget": [ ... ],
  "analysis": [ ... ],
  "suggestions": [ ... ],
  "summary": "..."
}
```

**Error Response — `400 Bad Request`:**

```json
{
  "success": false,
  "error": "Please provide a valid positive monthly income."
}
```

### GET /api/key-status

Returns the current AI engine mode based on the server-side API key configuration.

**URL:** `GET /api/key-status`

**Request:** No body required.

**Success Response — `200 OK`:**

```json
{
  "configured": true,
  "mode": "gemini"
}
```

| Field | Type | Values | Description |
|---|---|---|---|
| `configured` | boolean | `true` / `false` | Whether a valid API key is configured server-side |
| `mode` | string | `"gemini"` / `"smart_engine"` | Current active analysis engine |

**Notes:**
- This endpoint only reflects the server-side `.env` key. It does not know about keys stored in the client's `localStorage`.

---

### POST /api/key-status

Sets a new Gemini API key at runtime. Attempts to persist the key to `.env` for durability
across server restarts.

**URL:** `POST /api/key-status`

**Request Body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `api_key` | string | Yes | The new Gemini API key |

**Example Request:**

```json
{
  "api_key": "AIzaSyXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
}
```

**Success Response — `200 OK`:**

```json
{
  "success": true,
  "message": "API Key saved successfully! Live Gemini AI is now active."
}
```

**Error Response — `400 Bad Request` (invalid or placeholder key):**

```json
{
  "success": false,
  "error": "Invalid API key format."
}
```

**Side Effects:**
- Sets `os.environ["GEMINI_API_KEY"]` and `os.environ["GOOGLE_API_KEY"]` in the running process.
- Overwrites `.env` file if the server has write permission.

### GET /health

Lightweight health check endpoint. Returns the current server status and AI mode.

**URL:** `GET /health`

**Request:** No body required.

**Success Response — `200 OK`:**

```json
{
  "status": "ok",
  "mode": "smart_engine",
  "api_key_configured": false
}
```

| Field | Type | Values | Description |
|---|---|---|---|
| `status` | string | `"ok"` | Always `"ok"` when the server is running |
| `mode` | string | `"gemini"` / `"smart_engine"` | Current active AI engine |
| `api_key_configured` | boolean | `true` / `false` | Whether a server-side API key is set |

## Error Responses

All error responses follow this shape:

```json
{
  "success": false,
  "error": "<human-readable error message>"
}
```

| HTTP Status | Cause |
|---|---|
| `400 Bad Request` | Invalid JSON body, missing income, no valid expense categories, value out of bounds, invalid API key format |

The server does not return `401 Unauthorized`, `403 Forbidden`, or `404 Not Found` from the application
routes (Flask serves a 404 for unrecognised paths, but the app does not use auth middleware).

---

## Validation Rules

Enforced by `validate_input()` in `app.py` before any AI call:

| Rule | Details |
|---|---|
| `income` must be a positive number | `isinstance(income, (int, float)) and income > 0` |
| `income` must not exceed `10,000,000` | Rs 1 crore upper bound |
| `expenses` must be a non-empty dict | At least one entry required |
| Expense keys must be in the whitelist | Unknown keys are stripped silently |
| Expense amounts must be `>= 0` | Negative values are stripped |
| Each expense must not exceed `5,000,000` | Rs 50 lakh upper bound per category |
| `goal` must be one of 8 valid values | Invalid goal defaults to `emergency_fund` |

## Quick Reference cURL Examples

```powershell
# Health check
curl http://127.0.0.1:5000/health

# Analyse with Smart Engine (no API key)
curl -X POST http://127.0.0.1:5000/analyse `
  -H "Content-Type: application/json" `
  -d '{"income":60000,"expenses":{"rent":18000,"food":7000,"dining":3000},"goal":"investment"}'

# Check API key mode
curl http://127.0.0.1:5000/api/key-status

# Set an API key at runtime
curl -X POST http://127.0.0.1:5000/api/key-status `
  -H "Content-Type: application/json" `
  -d '{"api_key":"AIzaSyYOURKEYHERE"}'
```
